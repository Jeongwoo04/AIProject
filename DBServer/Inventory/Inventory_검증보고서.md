# Inventory 시스템 검증 보고서

## 1. 검증 범위 및 기준

이 보고서는 Inventory 기획서와 제공된 Legacy Code, 이전 작업에서 실제로 논의·수정한 사항을 기준으로 작성했다. 확인하지 않은 빌드, 실행 테스트, GameServer 통합 테스트를 통과한 것으로 기록하지 않는다.

## 2. 직접 검토·반영한 사항

| 항목 | 검토 내용 및 반영 사항 | 확인 수준 |
|---|---|---|
| 수량 변경 인터페이스 | Inventory의 적재·중첩·부분 제거·사용 후 수량 변경 경로에서 Item의 수량을 변경해야 하므로 `TrySetCount()`가 필요하다는 점을 확인하고 호출하도록 반영 | 코드 연동 검토 |
| 수량 유효성 | 수량 변경은 0 이하 또는 `MaxStackCount` 초과가 되지 않도록 Item 측 검증 함수에 위임하는 구조로 정리 | 설계/코드 검토 |
| 적재 정책 분리 | 월드 루팅은 부분 적재, 보상·구매·교환은 전체 적재 성공 방식으로 구분 | 정책 확정 및 코드 반영 확인 |
| 적재 순서 | 기존 동일 Definition 스택을 먼저 채우고 남은 수량을 빈 슬롯에 배치하도록 정리 | 코드 흐름 검토 |
| 실패 시 상태 보존 | `AllOrNothing`의 사전 `CanFit()` 검사로 공간 부족 시 슬롯 변경 전에 실패하도록 구성 | 코드 흐름 검토 |
| Count 검증 흐름 | Count 변경 전후의 유효 범위를 고려해 검증 책임을 `TrySetCount()`에 모으고, 적재·이동·제거·사용 흐름에서 직접 Count를 임의 변경하지 않도록 정리 | 코드 흐름 검토 |
| 슬롯 이동/중첩 | 빈 슬롯 이동, 동일 Definition 중첩, 서로 다른 Definition 교환으로 분기 | 코드 흐름 검토 |
| 사용 후 수량 처리 | `Item::Use()` 성공 후에만 수량을 차감하고, 실패 시 Inventory 상태를 유지하도록 구성 | 코드 흐름 검토 |
| 소유권 | `unique_ptr` 이동으로 Inventory와 호출자 사이의 Item Instance 소유권 이전을 표현 | 코드 구조 검토 |

## 3. 코드에서 확인한 조건 및 처리

- 슬롯 유효 범위는 `0 <= slotIndex < 40`이며 범위를 벗어나면 조회는 `nullptr`, 변경 함수는 실패를 반환한다.
- `TryAddItem()`은 null 입력과 Count/MaxStackCount의 기본 범위를 검사한다.
- `CanFit()`은 기존 동일 Definition 스택의 여유 공간과 빈 슬롯 수용량을 합산한다.
- `RemoveCount()`는 0 이하 수량, 빈 슬롯, 보유 수량 초과 제거를 거부한다.
- `MoveItem()`은 잘못된 슬롯, 동일 슬롯, 빈 출발 슬롯 및 중첩 공간 부족을 거부한다.
- `UseItem()`은 슬롯 및 Item 존재 여부를 확인하고 `Use()` 실패 시 Count를 변경하지 않는다.
- `Clear()`는 각 슬롯의 `unique_ptr`를 reset한다.

위 항목은 제공된 코드의 조건문과 처리 흐름을 확인한 결과이며, 별도 실행 테스트 결과를 의미하지 않는다.

## 4. 실행 테스트 여부 및 미검증 항목

현재 제공된 자료와 이전 작업 기록에서 테스트 실행 결과가 확인되지 않는 항목은 통과로 기재하지 않았다.

- 40개 슬롯 경계값에 대한 실행 테스트
- `CanFit()`의 다양한 스택/빈 슬롯 조합에 대한 실행 테스트
- `AllOrNothing` 공간 부족 시 슬롯이 변경되지 않는지에 대한 실행 테스트
- `Partial` 적재 후 호출자 Item의 잔여 Count 및 소유권 확인 테스트
- `MoveItem()`의 이동·중첩·교환 및 실패 원복 테스트
- `RemoveCount()`의 전체/부분 제거 및 경계값 테스트
- `UseItem()`의 사용 성공/실패 및 마지막 수량 제거 테스트
- Player 생성/제거 및 실제 GameServer 요청 처리 흐름 통합 테스트
- 드랍 객체 생성 실패, 상점/교환/보상과 재화 변경의 원자성 테스트
- 동시 요청, 중복 요청 및 DBServer 저장 연동 테스트

또한 제공된 Inventory Legacy Code는 `Item::TrySetCount()`와 `Item::Use(Player&)`에 의존한다. Item Legacy Code의 실제 최종 선언과 일치하는지, 전체 솔루션에서 빌드되는지 별도 확인이 필요하다.

## 5. 종합 결과

현재까지 확인 가능한 성과는 Inventory 정책의 구분, Count 변경 인터페이스 필요성 확인 및 코드 반영, 그리고 적재·이동·제거·사용 흐름의 코드 수준 검토다.

다만 위 기능들의 실행 테스트 통과나 기존 GameServer와의 통합 완료를 입증하는 결과는 확인되지 않았다. 따라서 본 보고서는 실제 실행 테스트 성적서가 아니라 **직접 논의·반영한 설계 및 코드 검토 사항과 미검증 범위를 구분한 보고서**다.
